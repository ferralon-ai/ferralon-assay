# v0.3.0

v0.2.0 shipped five-language coverage where each lane completes a scan. v0.3.0 is about
depth: real call-graph analysis per language, a new decisive supply-chain signal, and the
operational hardening a scanner needs before anyone pins it in their CI.

### Analysis depth, per language

- **Java.** JVM bytecode parser, class-hierarchy-analysis call graph over cached JARs, and a
  two-trace non-exploitability engine.
- **Analysis substrate.** A language-agnostic foundation shared across lanes — symbol model,
  plugin contract, dependency inventory, and the evaluation harness.
- **JavaScript / TypeScript.** Dependency-inventory resolution across npm, pnpm, and Yarn, and
  across bundler configurations.
- **.NET.** ECMA-335 metadata reader, dependency inventory, and IL call-graph reachability.
- **Python.** Dependency resolution, build manifest, and SBOM projection.

### A new decisive signal

- **Malicious-package presence.** When a known-malicious package resolves to a version the
  advisory enumerates as affected, Assay emits a decisive "affected" verdict. It fires only on
  an affirmative presence match — absence, a version not listed, or an unresolvable dependency
  emit nothing.

### Corpus scaffolding

- Symbol-provenance store, provenance-as-confidence (a candidate-only strength label), and a
  PoE exploit-precondition qualifier — the groundwork for the external vulnerability corpus.

### Operational hardening

- Pull-request CI: build, `go vet`, `gofmt`, and tests on every PR.
- A per-language capability matrix in the README, reconciled with the Quickstart's scope.
- Release hygiene: commit-SHA pinning guidance, a split-out threat model, and disclosure of the
  self-cleanup behavior.
- **Self-cleanup on revoke, with an operator opt-out.** The removal ladder that retires the
  Action after a signed, repository-bound install-revoke is confirmed now has an explicit
  operator opt-out (`self-cleanup-on-revoke`) — see [docs/threat-model.md](../threat-model.md).
