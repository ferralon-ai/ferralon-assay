# v0.3.1

A repository can now tell Assay which ref to scan. By default nothing changes — Assay scans the ref CI checked out, exactly as before. A repository whose scannable source lives off its default branch (a docs-only default, a release branch, a historical baseline) can opt in with a small config file and have Assay analyze that ref instead.

### Choosing the analyzed ref

- **`.github/ferralon.yml`** — an optional, opt-in config file. Set `analyze.ref` to a branch, tag, or commit and Assay fetches that ref, checks it out in an isolated worktree, and analyzes it. Absent the file or the key, behavior is unchanged.

  ```yaml
  version: 1
  analyze:
    ref: baseline
  ```

- **Honest provenance.** With an override in effect, the Report records the ref actually analyzed and its resolved commit — never the CI ref it was told to scan.
- **Safe by construction.** The config parses as data under a strict schema (unknown keys warn, malformed fails closed); the ref is validated and passed to git as an argument, never a shell string; and the override is analyzed in a throwaway worktree, so the checked-out workspace is never moved.

### Clearer guidance when there's nothing to scan

- The "not a recognized source tree" error now names every supported language marker and points at `analyze.ref`, so a repository whose source is on another branch is told how to fix it.
