# v0.3.2

This release widens what Assay analyzes — Kotlin services reach Java-level entry-point coverage, and a Go module is found wherever it lives in a repository — and refines when a designated-ref assessment is delivered.

### Kotlin reachability reaches Java parity

Kotlin now recognizes the same JVM entry-point families as Java, drawn from one shared registry instead of a hand-maintained Kotlin list. Entry points the Kotlin lane previously missed — JAX-RS routes, `@Scheduled`, `@EventListener`, `@PostConstruct`/`@PreDestroy`, Kafka/JMS/Rabbit listeners, and `HttpServlet` subclasses — now seed reachability alongside Spring HTTP routes. More recognized entry points can only raise reachability, so a Kotlin service may surface an exploitable path a prior release treated as unreachable.

### A Go module anywhere in the repository

Assay previously required `go.mod` at the checkout root; a repository whose Go module lives under a subdirectory (`target/`, `src/`, a service folder) fell through to language guessing or "not a recognized source tree." Assay now searches for the module — bounded and deterministic — and analyzes it wherever it sits, so monorepo- and service-shaped layouts are recognized as Go with no configuration.

### Full assessment when the analyzed ref is the canonical one

Building on v0.3.1's `analyze.ref`: the delivery gate now asks what a run *analyzed*, not only what triggered it. A repository that designates a ref in `.github/ferralon.yml` gets its full assessment delivered on any run that analyzed that canonical ref — a push to the ref itself included — where before only a default-branch trigger qualified. With no `analyze.ref` set, the canonical ref is the default branch and the decision reduces exactly to the previous condition, so a plain repository sees no change.

### Library surface

For code importing Assay as a Go module: `verdict.BasisStaticRefutation` is a new `NonExploitableBasis` value recording a held static proof-of-non-exploitability over a complete analysis, and `pipeline.InventoryCheckoutRoot` reads back the checked-out directory (honest-absent on records written before this release).
