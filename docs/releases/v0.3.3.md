# v0.3.3

This release lets Assay read the advisory corpus as one prebuilt bundle file instead of a checkout of the whole record tree, and makes every tag of the Action name exactly one scanner release.

### Scan against a corpus bundle

`-advisory-corpus` (and its environment variable) now accepts a corpus bundle file, `<policy>.jsonl.gz`, as well as a corpus directory. Assay tells them apart by what is on disk. From there both behave the same: a corpus that cannot be read fails the run, the corpus is consulted ahead of the built-in advisory table, and the `Report` records where its facts came from. For a bundle, the `Report`'s corpus digest is the sha256 of the `.gz`, the same value the corpus release publishes for it in `bundles.json`. Every record is checked against its own digest when it is read.

In the Action, the new `advisory-corpus-policy` input picks one corpus policy, for example `published-7d` or `full`. When the corpus release has a bundle for that policy, the Action downloads that single file from the `corpus-*` release named by `advisory-corpus-ref`, where the default `main` means the most recent release. It checks the file before the scan:

- the bundle's sha256 must match the release's `bundles.json`;
- the policy manifest, read from the git commit the release tag points at, must match its `bundles.json` digest;
- the bundle must carry exactly the manifest's records.

Any mismatch fails the run. A policy the release has no bundle for is read through the existing git fetch, at the same release tag, using that policy's manifest. With `advisory-corpus-policy` unset, the Action behaves as before.

These checks detect a corrupt, truncated or mismatched bundle. They do not make an unsigned release trustworthy: the release assets, the tag and the git tree all come from the same repository, so whoever can publish a release can make every check pass.

### Every Action tag names one scanner release

`scanner-version` on a branch is a minor alias, `vX.Y`. The Action resolves it at run time to the patch release that the repository's `vX.Y` tag points at. That tag moves only after a release has finished publishing. Each release tag's `action.yml` names its exact scanner release, so `uses: ferralon-ai/ferralon-assay@v0.3.3`, or that tag's commit SHA, always fetches the v0.3.3 scanner. `@v0.3` fetches the latest v0.3 patch. The run log shows which release an alias resolved to.

`scanner-sha256` pins exact bytes, so it now requires an exact `vX.Y.Z` `scanner-version`. A checksum paired with an alias fails the run before anything is fetched.

### Library surface

For code importing Assay as a Go module: `pipeline.NewBundleSource(path)` returns an `AdvisorySource` over one corpus bundle file. It reads the file once, checks each record's digest on lookup, and fails closed. It implements `CorpusValidator` and `CorpusDescriber` like the directory reader, plus `AdvisoryEnumerator`.
