# v0.4.0

This release makes a declared advisory policy decide what a scan evaluates, adds an honest `indeterminate` verdict for runs that established nothing, and settles the names of the scanner's analyzer binaries and first-party advisory ids. Several of these changes break existing setups, so read the first section before you upgrade.

### Before you upgrade

**Move your Action pin.** `@v0.3` keeps fetching the latest v0.3 patch. To get this release, pin `uses: ferralon-ai/ferralon-assay@v0.4.0` (or that tag's commit SHA), or `@v0.4` to follow v0.4 patches. If you set `scanner-sha256`, update it to the v0.4.0 tarball's checksum.

**`advisory-corpus-policy` now defines the scan's work set.** Before, a policy only chose which advisory facts were available, so `published-24h` and `full` scanned the same advisories. Now a declared policy means: the built-in floor, plus every advisory in that policy whose affected package is one of your repository's own dependencies. The version range is still checked per advisory during the scan. Expect a policy run to evaluate more advisories than it did on v0.3, and to make no OSV.dev query, even with `-osv-work-set`. What to check:

- In the Action, the policy applies on the `advisory-corpus-repo` route and is ignored when `advisory-corpus` is set, as before. With `advisory-corpus-policy` unset, nothing changes: the corpus still supplies facts only.
- On the CLI, declare it with `-advisory-corpus-policy` or `ASSAY_ADVISORY_CORPUS_POLICY` (the flag wins). It requires `-advisory-corpus`.
- If you parse the `Report`: `work_set_source` has a new value, `builtin_language_set_union_policy`, and the declared policy is recorded as `corpus_policy`. There are three new partiality reason codes. `policy_advisory_no_coordinates` counts policy advisories that name no affected package; it is an inherent limit, disclosed in the analysis-limits footer without qualifying the headline. `policy_advisory_unresolvable` counts records that failed validation. `work_set_policy_not_enumerable` means the corpus reader couldn't list the policy's ids, and the run fell back to the v0.3 behaviour. Each note gives the exact count and names up to twelve ids.

**Analyzer plugins are named `assay-plugin-<lang>`.** The CLI looks each analyzer up on `PATH` under that name. If you run the CLI outside the Action, reinstall the analyzers from `./cmd/assay-plugin-<lang>` (`go`, `java`, `kotlin`, `js`, `python`, `dotnet`), as the README's quickstart shows. Release asset names don't change, and the Action wires the new names itself.

**First-party advisory ids use the `FERRALON-` prefix.** This only affects scans run with `include-house-canaries`. The advisory ids, and the SARIF `ruleId`s built from them, change, so code-scanning alerts and stored baselines keyed on the old ids close and reopen once after you upgrade.

**The PoE schema ids move to v2.** A PoE's direction can now be `indeterminate` (see below), so `verdict.SchemaVersion` and `projection.RedactedPoESchemaVersion` bump from `.v1` to `.v2`. The payload shapes are unchanged. If you validate PoE payloads, accept the v2 ids and the new direction and strength value.

**For code importing Assay as a Go module:**

- Library packages no longer read process environment. Pass the settings explicitly: `telemetry.Config` gains `Level`, `SampleRatio` and `Environment`; `plugin.NewJavaPlugin` takes `plugin.WithJavaAnalyzerImage` and `plugin.WithJavaAnalyzerDocker`; `github.DetectEnv` takes a `github.Toggles`.
- `projection.SARIFProperties`' extension field is now `Scanner`. Its JSON tag, `scanner`, is unchanged.
- `verdict.Validate` rejects a reasoned `not_exploitable` with no `NonExploitableBasis`. An ungrounded lean is now an `indeterminate` verdict.
- `plugin.BinaryName(language)` returns an analyzer's lookup name.

### A verdict for "nothing was established"

Before, a run that executed but proved nothing had to land on `exploitable` or `not_exploitable`, and the safe-looking one said something the run hadn't shown. `indeterminate` is now a first-class value (`verdict.DirectionIndeterminate`, always paired with `verdict.StrengthIndeterminate`). It carries no proof flags, basis or reproducer, and every projection treats it as unknown rather than safe: SARIF level `none` with kind `review`, the kind SARIF uses for results a person needs to look at; SSVC exploitation `none`, automatable `no`. Corpus fixtures can expect it too.

### `pr-inherit` leaves the baseline alone

`pr-inherit` no longer writes to the state store. When a PR changes dependencies it still re-analyzes the affected advisories and merges them over the inherited findings, but it only publishes that Report. Before, it overwrote the default branch's stored baseline with a Report of unmerged code, which the next PR inherited from and `cve-watch` diffed against, and on a fork PR the read-only token made the run fail. A read-only token is now enough, fork PRs included.

### Analysis fixes

- **Go: SSH server input is an attacker-controllable ingress.** A function taking a `golang.org/x/crypto/ssh` `ServerConn`, `ConnMetadata`, `NewChannel`, `Channel` or `Request` is now an `ssh` ingress, and its parameters are taint sources. A vulnerable call reached through an SSH handler can now grade `attacker_tainted` instead of `control_flow_only`.
- **Python: templated requirements files.** A `requirements` line carrying Jinja delimiters (`{`, `}`, `%`) no longer becomes a junk SBOM node. A templated name drops the line; a templated version keeps the package with an unresolved version. Plain pins inside a template block still parse.

### Faster directory corpora

The directory corpus reader now reads and validates `manifest.json` once and indexes it, where before it re-read the whole manifest on every lookup. At the start of each assessment it checks whether the manifest changed and reloads it if so, which keeps long-running processes current. A failed reload keeps serving the last good manifest and reports the error, and every advisory document is still checked against its digest on every lookup.

### Docs

- A new [operator guide](../operator-guide.md) covers reading a Report, how the subject Go toolchain is resolved, the StateStore and each run mode, and which publish surface fires under which permissions, forks included.
- The README's advisory corpus section now documents the corpus environment variables and `-require-advisory-corpus`.
- The [release guide](README.md) and a new root `AGENTS.md` state that releases are cut only by pushing a tag. `scripts/build-release.sh` prints a reminder when run locally; `ASSAY_LOCAL_BUILD=1` silences it.

### Library surface

Additions: `pipeline.CorpusRefresher`, an optional interface the directory reader implements and `pipeline.NewChainSource` forwards; `verdict.DirectionIndeterminate` and `verdict.StrengthIndeterminate`; `github.Toggles`; and the `telemetry.Config`, `plugin.WithJavaAnalyzerImage`, `plugin.WithJavaAnalyzerDocker` and `plugin.BinaryName` changes listed above.
