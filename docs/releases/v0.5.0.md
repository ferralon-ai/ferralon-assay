# v0.5.0

This release makes `not_exploitable` rest on named grounds, reports more of what a scan could not settle as `undetermined` rows instead of dropping or guessing, and deepens dependency analysis for Java, Kotlin, .NET, Python and JavaScript. Read [Before you upgrade](#before-you-upgrade) before you move your pin: the Action pin moves, the Report gains rows and fields, and Go library importers have one API change.

In every ecosystem, a `not_exploitable` row now needs an admitted package with a resolved version and either a complete search from the entry points or a positive refutation of the package; anything short of that is `undetermined`, with the missing ground as its reason. Advisories a scan used to drop, because their assessment failed or they carry no bounded range, now appear as counted rows. Go grounds its verdicts on govulncheck's own evidence. Java and Kotlin search the compiled program and its dependency JARs, decide Maven profiles from conditions you state, and Kotlin can now return `not_exploitable` from an empty search. .NET resolves advisory symbols inside the restored NuGet assemblies for the build's target. Python and JavaScript bind imports to the packages that provide them and trace call paths into those dependencies. A new `resolve-graph` command writes a Maven or Gradle build's resolved dependency graph.

### Verdicts and analysis

**All ecosystems**

- `not_exploitable` needs named grounds. A row needs an admitted package with a resolved version, and either every advisory symbol resolved inside that package and searched from the entry points, or a positive refutation of the package. Anything less is `undetermined` with the missing ground as its reason (#82). An advisory that names another package is `undetermined` for that package (#82), and a `package_not_loaded` refutation grounds `not_exploitable` only on a record that lists every affected package (#105).
- An advisory whose assessment fails appears as an `undetermined` row (`analysis_did_not_run`) in baseline, PR and CVE-watch runs. Its detail names the failed step and a redacted error (#142).
- A reachable path to an advisory with no bounded version range for the admitted package is `undetermined` with `advisory_range_absent`, path kept as evidence, in place of `reachable_candidate` (#108).
- The version axis honors each range's `introduced` lower bound (#118).
- Version disqualification fires only when every version of the package the codebase carries is outside the range, and the plugin vouches it saw them all (#124).
- An advisory against the scanned project's own package is adjudicated against the project, read from `go.mod`, `package.json`, `pyproject.toml`/`setup.cfg`, `pom.xml`/`build.gradle` or a single `.csproj`, instead of being dropped (#109).
- The published corpus's `affected[]` packages are read, so multi-package records are seen as multi-package (#91).
- A dependency with no resolved version is admitted by name and gets an undetermined row. The OSV query still asks only about resolved coordinates, and each skipped dependency is named under `work_set_dependency_unresolved` (#136). Policy admission compares PyPI names per PEP 503 and NuGet ids lowercased (#110).
- A scoped limit blocks `not_exploitable` only for the packages it can reach (#84).
- `ReachabilityRequest.Package` carries the admitted package, and a lane emits `package_not_loaded` only when it is set (#92).
- The dashboard Issue opens or updates only on default-branch runs; PR runs and other branches still publish the job summary, SARIF and the sticky PR comment (#139).

**Go**

- `not_exploitable` rests on govulncheck's evidence. No finding at all is `undetermined` with `advisory_unknown_to_analyzer`; module or package findings without a symbol finding refute the module, naming version, GOOS/GOARCH and build tags (#83).
- A cgo boundary blocks `not_exploitable` only for the modules its hidden code can reach (#85).
- A Go advisory on a package that no module of the build holds is `not_exploitable`, grounded on a search of every module's source (#144).
- GO-2021-0264 carries its Go toolchain ranges: fixed in go1.16.10 on the 1.16 branch and go1.17.3 on mainline (#141).
- The library-escape check reads `internal` only below the module path (#117).
- Reach traces come out in a fixed order (#89).

**Java and Kotlin**

- A Java advisory on a Maven dependency resolves against the dependency's own JAR from the local Maven or Gradle cache (#111). Reachability searches the compiled program: the build's class output plus one JAR per runtime-classpath dependency, transitive ones included (#113).
- Kotlin traces reachability through the resolved dependency closure. It is the first JVM lane that can return `not_exploitable` from an empty search, for Gradle builds with a lockfile and complete Maven builds (#99).
- The shared JVM engine never returns `not_exploitable` across a dependency it did not open, and method resolution follows superclasses then superinterfaces for default bodies (#78).
- Maven profile activation is decided from stated facts (`--subject-maven-profiles`, `--subject-java-version`) in place of a run-wide `profile_activation` reason (#114, #146). An imported BOM's undecided managed versions are withheld (#148).
- A Maven or NuGet match resolves only when every copy is modeled and all copies agree (#138). A Maven parent outside the tree is read from the local Maven repository or Gradle cache, and the match is withheld when it can't be (#140, #143). A Maven wrapper counts as stock only when every line is plain printable ASCII (#132).
- A plain Spring Boot app's launch entry is the `main` that `spring-boot-maven-plugin` finds (#147).
- Class literals such as `B.class` and `int[].class` parse as expressions, which stops phantom classes and misattributed calls (#86).

**.NET**

- An advisory symbol in a NuGet package resolves inside the package's restored assemblies, found through `project.assets.json` and bound to the build's target framework and runtime (#80).
- A straddling dependency version stays unresolved, and every input MSBuild or NuGet consults is read or withholds (#104). A plain `PackageReference` version is a minimum; only `[1.2.3]` resolves (#128).
- The CVE-2024-21907 (Newtonsoft.Json) advisory names every read path, including the private `JsonReader.Push` (#101). A build on a target that does not compile every floor symbol can be `not_exploitable` (#145).

**Python**

- Imports bind to distributions, function-local imports included, and a call through one becomes an edge to a `pypi:<dist>#<path>` boundary node. Module-level and class-body calls get a `<module>/__init__` caller (#88). Namespace and alias imports (`azure.*`, `dotenv`, `jwt`, `PIL`, `dateutil` and others) attribute by longest curated package (#107).
- Manifest and version coverage grows: poetry.lock and pip-compile edges, setup.cfg, setup.py literals, PEP 621 dependencies and hatch sources. Ranges are reported as unresolved with the specifier kept. The `no_manifest_entry` guard now covers PyPI and npm (#97).
- Requirements continuations join as pip joins them (#126). A conda recipe makes the dependency set non-exhaustive (#125).
- A filesystem error other than a missing path counts as unread, never absent (#133). In-tree symlinked `site-packages` and metadata entries are read at their targets (#135).

**JavaScript**

- Module top-level code gets a `<module-init>` frame, calls inside callback arguments are attributed, and inline route handlers get their own frame (#79).
- First-party calls into a dependency record an edge to an `npm:` boundary node, with an Express receiver model, so the scan can report a call path into the dependency (#95).
- Every out-of-tree package load declares `uninspectable_package`, and computed loads declare `computed_require` (#81).
- A package installed at several versions stays unresolved (#98). A filesystem error other than a missing path counts as unread (#130). In-tree symlinked `node_modules` are followed (#135).

**Python and JavaScript, shared**

- A pipe, socket or device in the build tree is never opened (#120, #121). Files with NUL bytes or a byte-order mark are judged instead of dropped (#122).

**C/C++**

- The C/C++ lane is in the source tree but not in the scanner release asset, so the Action's behavior on C/C++ repositories does not change (#69, #74-#76, #94, #102, #119, #127).

### Report format

All additive. A consumer that ignores unknown fields and unknown `undetermined_reason` values keeps working.

- New optional fields: `Package.root`, `Package.replace`, `SBOM.go_build_list`, `SBOM.go_main_module`, `EvidenceSummary.advisory_bounds`, and `PartialityNote.package` and `.path`.
- New `undetermined_reason` values: `package_version_unresolved`, `advisory_symbol_absent`, `vulnerable_symbol_unresolved`, `advisory_unknown_to_analyzer` and `advisory_range_absent`.
- `Validate()` rejects `advisory_bounds` on a finding whose reason isn't `advisory_range_absent`.
- New partiality codes: `ifdef_config_variance`, `native_link_boundary`, `macro_expansion` (#74), and `work_set_dependency_unresolved` (#136). `dynamic_dispatch:fn_ptr` and `dynamic_dispatch:vtable` are classed as limits of the method (#74).
- `report.Package.Label` renders a found-but-unresolved package as, for example, `zlib (pinned 1.2.11, not resolved)` (#119).

### CLI

Two new optional flags state conditions of the scanned repository's Maven build; Assay never looks either up.

- `--subject-java-version` (env `ASSAY_SUBJECT_JAVA_VERSION`): the `java.version` of the JVM that runs the scanned build, as `mvn -v` reports it, for example `17.0.12` or `1.8.0_382`. It decides Maven profiles activated by `<jdk>`. Unset, those profiles are reported as undecided.
- `--subject-maven-profiles` (env `ASSAY_SUBJECT_MAVEN_PROFILES`): the build's explicit profile selection in `-P` syntax, covering its `-P` list and `settings.xml` `<activeProfiles>`, for example `release,!docs`, or `,` for none. Unset, every profile of the reactor and its parents is undecided. The flag wins over the env var.

The pipeline hands both to inventory resolution, symbol mapping and reachability, so one run resolves Maven under one set of conditions (#114, #146).

A new `resolve-graph` command runs the repository's own Maven or Gradle and writes its resolved dependency graph as `assay.buildgraph/v1` JSON, with the build's inputs hashed alongside. It takes the build tool (`-tool auto|maven|gradle`), Maven profiles, the stated JDK, build properties and environment. A resolution that fails prints a typed cause, exits non-zero and writes no graph. A scan does not read this graph yet (#153).

### Performance

- A disqualified advisory skips symbol mapping and reachability (#87, #90).
- Tree-only plugin operations (call graph, ingress discovery, manifest and inventory reads, symbol indexing, version resolution) run once per distinct request per scan (#96).

### Docs

- `docs/language-support.md` and the `action.yml` header no longer state that `not_exploitable` always rests on a search (#77).

### Library surface

Additions: the `buildgraph` package (#153); `plugin.Memoize`; `pipeline.WithSkipDisqualifiedAnalysis`, `pipeline.CanonicalName`, `pipeline.AdvisoryListsAffectedPackages` and `pipeline.AdvisoryRangeAbsent`; `ReachabilityRequest.Package`; `TargetEnv` on `ReachabilityRequest` and `ResolveSymbolsRequest`; `DependencyVersionResult.Matches` and `MatchesComplete`; `SymbolResolutionResult.ModuleSearch`; `plugin.Partiality.Scoped`; `AdvisoryFacts.TargetConditionalSymbols`; `report.Package.Label`; and `PrimaryRuntime()` and `PrimaryResolver()` on `plugin.BuildManifestResult`.

### Before you upgrade

**Move your Action pin.** Workflows pinned to `@v0.4` or `@v0.3` keep fetching those releases. To get this release, use `uses: ferralon-ai/ferralon-assay@v0.5` (or `@v0.5.0`, or that tag's commit SHA). If you set `scanner-sha256`, update it to the v0.5.0 tarball's checksum. Leave `scanner-version` unset and the tag runs the v0.5.0 scanner. No Action input or output changed.

**Expect more rows, and some rows to change verdict.** A scan now counts advisories it used to drop, and some rows that were `undetermined` are now `disqualified` or `not_exploitable`. The changes behind this are listed under "Verdicts and analysis".

**Parsing the Report?** Everything in the Report is additive; see "Report format".

### Breaking (library API)

This affects Go code that imports Assay as a module, and analyzer plugins built outside this repository. Nothing changes for the CLI, the Action or the Report.

- #73 `plugin.BuildManifestResult` drops `Resolver`, `Runtime` and `Target`. It carries `Runtimes []RuntimeSpec` and `Resolvers []ResolverSpec` instead. Each `RuntimeSpec` holds its own `Target`, `Lang` and `StdLevel`, plus a `Source` of `declared`, `ambient` or `compile_db`. To migrate, read `result.PrimaryRuntime()` and `result.PrimaryResolver()` where you read the single fields (each returns false for zero or several), or range over the sets.
- #73 The plugin wire shape changes from `"runtime"`/`"resolver"` objects to `"runtimes"`/`"resolvers"` arrays. The plugins in the release asset ship with the host; a plugin built outside this repository must move to the new shape to work with a v0.5 host.
